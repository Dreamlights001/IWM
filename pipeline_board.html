链路看板：从 STEP、扫描和 URDF 出发

假设手头有：机床等生产设备的 STEP 文件，这些设备实物的三维扫描，以及一台带 URDF 的机器人（人形、小车或机械臂）。下面列出能用这些输入搭起来的世界模型链路，每条附实现步骤、时延、证据、局限和参考项目。

本看板只列举链路，不做推荐。链路之间不互斥，常常组合使用；排列顺序按输入从“只用 STEP”到“需要更多现场数据”，不代表优先级。时延数字来自各论文在各自硬件上的报告，不能直接横向比较。形变、流体、断裂与加工不作为单独链路，而是任务条件，见跨链路条件一节。

输入与链路的对应

左边是输入，右边是链路。实线表示该链路需要这项输入，虚线表示可选。STEP、扫描和 URDF 是已有的；PLC／NC、视频和工艺信号是部分链路额外需要的。点右边的链路名跳到详情。

L1

STEP 资产化＋物理仿真作为世界模型

所属路线：显式仿真

STEP 文件机器人 URDF实物扫描（可选）
  1. STEP 清理去掉螺钉、倒角等小特征；拆出运动部件（轴、门、卡盘、夹具、按钮）；统一单位与坐标系
  2. 导出视觉网格与碰撞体视觉用细网格；碰撞体做凸分解或用简单形状；装夹面、按钮、插接面保留能分辨任务公差的几何
  3. 写关节与驱动机床轴、门、夹具写成关节（URDF／MJCF／USD），设定行程、限位、驱动方式；机器人直接加载已有 URDF
  4. 组装场景机床、机器人、料架、工件放进同一坐标系；校核质心、惯量、摩擦
  5. 推演与规划仿真器作为转移函数：给定动作推演结果，做 MPC 或离线评估策略
预测什么
机器人与机床部件的运动、接触、夹持；PLC 逻辑接入后还包括设备模式与事件（见 L4）
时延与成本
MuJoCo MPC 每次规划更新 1–20 ms（仿真中）；DROP 在真实灵巧手上 25–50 Hz（128 线程 CPU）P61P62
已有证据
MuJoCo、Isaac Sim、Gazebo 都能加载 URDF；ManiSkill3 原生支持 URDF 与 MJCF；IndustReal 在仿真中训练插装、齿轮装配并迁移到实机，实机插入成功率 80%、齿轮 97.5% P96P09P97
局限
每台机型都要人工拆部件、写关节和校参数；STEP 不含质量、摩擦、驱动和延迟；不含形变、流体、切削、磨损等（任务涉及时见下文“跨链路条件”）；仿真与现场会有偏差（见 L2、L3）。

L2

扫描配准到 STEP 资产，并校准成数字孪生

所属路线：显式仿真＋空间智能

STEP 文件实物扫描机器人 URDFPLC／NC 程序或日志（可选）
  1. 扫描现场激光或多视角相机扫描机床、工位与通道；记录尺度基准
  2. 重建得到点云或高斯（大范围可用激光惯导，局部用 SfM／前馈重建）
  3. 与 STEP 配准把 L1 的 STEP 资产与扫描点云做 ICP 配准，得到每台设备在现场的实际位姿；扫描里 STEP 没有的东西（线缆、护罩、料架）另作静态物体
  4. 外观与观测用扫描得到的高斯渲染现场外观，使仿真图像接近真实相机
  5. 辨识与同步用少量真实动作辨识摩擦、惯量、驱动增益、延迟；运行时用编码器与 PLC 信号持续把仿真状态拉回现场
预测什么
与 L1 相同，但初态、布局和外观来自现场，可与真实观测逐帧比较
时延与成本
Real-is-Sim 的数字孪生以 60 Hz 与现场同步 P58；RialTo 搭一个场景约 15 分钟人工，每个任务训练约 2 天 P59
已有证据
RialTo 扫描后导出 USD 到 Isaac Sim；ASID 主动设计少量真实交互来辨识物理参数；Real-is-Sim 用高斯＋粒子仿真器持续同步；DreMa、Robo-GS 用高斯渲染、物理引擎推进 P59P60P58P23P22
局限
机床多为反光金属和透明防护罩，扫描与重建容易出错；ASID 假设真实动力学落在已知参数化模型内；Real-is-Sim 的同步依赖视觉校正，封闭机床内部看不到。

L3

没有 STEP 的设备：扫描单体化后生成资产

所属路线：空间智能→显式仿真

实物扫描机器人 URDF现场视频＋动作记录（可选）
  1. 扫描并重建同 L2 的前两步
  2. 单体化把整片场景拆成对象实例：给高斯打实例标签，或用 2D 分割提升到 3D
  3. 补全补上被遮挡面、底面和接触面，得到完整对象
  4. 恢复关节从多个构型（门开／关、夹具开／合）的扫描中恢复部件与关节
  5. 转成可仿真资产估计或人工指定质量、摩擦，生成碰撞体，导出 URDF／USD，进入 L1
预测什么
与 L1 相同；资产精度取决于扫描与补全质量
时延与成本
SAGA 一次可提示三维分割约 4 ms P90；SceneAgent 转换一个场景需要反复调用 VLM，速度慢 P94
已有证据
Gaussian Grouping、SAGA、OpenGaussian 给出实例标签；InstaScene、DecoupledGaussian 补全对象；SceneAgent 从扫描生成含物理参数和关节的 OpenUSD；ArticulatedGS、ArtiTwinSplat 从多构型恢复关节 P89P90P91P92P93P94P26P27
局限
没有一种方法同时完成实例分离、补全、关节恢复并在工业场景中验证；透明、高反射物体普遍失效；物理参数未经实测校准；锁止、驱动、PLC 语义不能从外观恢复。

L4

设备逻辑联仿：PLC／NC 接入仿真，再接产线离散事件

所属路线：显式仿真＋结构化流程

STEP 文件机器人 URDFPLC／NC 程序或日志实物扫描（可选）
  1. 设备 I/O 映射把 L1 资产中的门、夹具、按钮、轴与 PLC／NC 的输入输出变量一一对应
  2. 接入控制器软件在环：虚拟 PLC／NC 运行真实程序或行为模型；或硬件在环：真实控制器连仿真对象
  3. 统一时钟物理步长、PLC 扫描周期、NC 插补周期在同一主循环或 FMI 联仿中对齐；记录请求、确认、到位三类事件
  4. 产线层工单、工艺路线、缓存、搬运、故障进离散事件队列；详细仿真的机床由仿真反馈完工，其余用校准过的周期模型
  5. 反事实换单、换路由、机床停机、机器人阻塞、返工的多场景推演
预测什么
设备模式、互锁、报警、程序推进、完工事件；吞吐、在制品、延期、资源争用
时延与成本
离散事件层运行很快；SIL 若控制器只支持实时时钟，则按实时推进；HIL 受真实通信周期约束 P98
已有证据
Siemens 指南示范 PLCSIM Advanced 运行 PLC 程序、SIMIT 模拟驱动、NX MCD 做机械仿真；LLM 智能体已能半自动生成 PLC 变量到仿真对象的映射；AWMP 在排产中预测外生订单 S30P66P38
局限
需要拿到 PLC／NC 程序或至少 I/O 变量表；商用虚拟控制器与特定机型绑定；规则维护成本高；日志中的相关关系不等于干预因果。

L6

仿真＋学习混合：残差、外观与快速代理

所属路线：显式仿真＋学习

STEP 文件机器人 URDF现场视频＋动作记录实物扫描（可选）
  1. 以 L1／L2 为底仿真负责已知物理和设备逻辑
  2. 残差用真实数据学习仿真与现场之间的偏差
  3. 外观仿真渲染图转成照片级图像，缩小视觉差距
  4. 快速代理用仿真数据训练图网络或三维动力学模型，替代慢的求解器
  5. 对照与原仿真、真实数据分别比较，确认代理没有引入新偏差
预测什么
与 L1 相同，但更接近现场或更快
时延与成本
MeshGraphNets 比原求解器快 11–289 倍；Cosmos-Transfer1 生成 5 秒 1280×704 视频，1 张 B200 约 142 s，64 张约 4.2 s P32P64
已有证据
在解析仿真上学习残差优于纯解析和纯学习模型；GNS、MeshGraphNets 学习粒子与网格物理 P63P31P32
局限
学到的代理会继承仿真偏差：只用仿真数据预训练的 PointWorld 不能零样本泛化到真实场景 P44；Cosmos-Transfer1 只重新渲染给定的仿真画面，不做动作条件预测。

L7

扫描场景中的三维动作条件动力学

所属路线：空间智能

实物扫描机器人 URDF现场视频＋动作记录PLC／NC 程序或日志（可选）
  1. 三维状态用深度相机或扫描得到场景点云或高斯
  2. 机器人动作接地用 URDF 正向运动学把机器人动作变成三维点或末端轨迹
  3. 学习转移训练模型预测动作引起的点流、高斯运动或对象刚体运动
  4. 规划用 MPPI／CEM 在模型中搜索动作
  5. 补设备状态门锁、PLC 模式等不能从点位移看出，需要作为额外条件输入
预测什么
机器人操作引起的三维几何变化（工件、门、夹具的位移）
时延与成本
PointWorld 一次批量前向约 0.1 s，预测 10 步 P44
已有证据
PointWorld 用约 200 万条轨迹训练，单个预训练模型让真实 Franka 无需额外示范或后训练即可完成推、可变形物体和关节物体操作；GWM 以高斯为状态做模型式强化学习；MRO-GWM 以对象为单位预测刚体运动 P44P85P88
局限
只覆盖几何层；设备内部状态、工艺、生产流都要另外接入；多为刚体与桌面规模。

跨链路条件：形变、流体、断裂与加工

这些不是单独的链路，而是任务中可能出现的物理情况。任务涉及它们时，走孪生路线（L1、L2，以及在其上运行的 L4、L6）需要能表示这些材料的仿真器；走学习路线（L7–L10）需要包含这些现象的数据，并检查模型是否学到了。原 L5「加工与形变过程模型」已并入本节，L5 编号空缺。详细说明见 链路/专题_形变流体断裂与加工。

任务涉及这些情况时，各链路要补什么

L1换用或接入支持该材料的求解器；STEP 只给几何，软体要生成四面体网格或粒子，并补弹性模量、粘度、摩擦等参数
L2材料参数要用现场观测辨识，例如 PhysTwin 用视频做逆物理 P21；形变体状态维度高，运行时同步比刚体难
L3软体要从接触面上分离并指定材料；切开或断裂后露出的内部没有扫描观测 P93P47
L4产线层不模拟材料，只需要工序时长、质量和报废概率，由下面的加工代理或实测统计提供
L6形变和流体仿真慢，适合训练快速代理：DINO-WM 报告形变环境中仿真推进一步约 3.0 s，模型前向一步约 0.014 s P07
L7点流和高斯能直接表示形变；断裂和切割会产生新表面，点之间的对应关系会断开 P44P21P19
L8训练数据要来自能表示该现象的仿真器或现场；DINO-WM 在 FleX 绳与颗粒任务上可行 P07；INTACT、SADL 还没有在这类任务上测试
L9切割、断裂不可逆，只能在仿真或学习式模型里试错
L10能生成形变和流体的画面，但不保证材料守恒和物理一致

加工（材料去除）

整厂层不直接预测切削，只需要加工时长、质量和报废概率，作为机床节点的属性。

  1. 毛坯与刀具几何工件 STEP 作为毛坯；刀具几何与刀路来自 NC 程序
  2. 材料去除用 dexel、体素或 SDF 扫掠更新工件占用域，输出去除体积与新表面
  3. 力、热与变形需要时耦合切削力、热流与结构变形模型
  4. 回写在同步点同时更新几何版本、碰撞体与质量；工件 ID 不变
  5. 校准用实测力、温度、尺寸与表面质量校准

Tri-Dexel 机器人铣削模拟器经铣削实验验证；热—力耦合 NC 模型预测宏观形状误差；DiSECt 做软材料切割的参数辨识，不能直接外推到金属切削 P48P50P46。论文未给统一时延：几何去除可较快，耦合有限元一般远慢于实时。

常见组合

链路之间通过共享资产、坐标系、实体 ID 和事件时钟组合。下表列出接口上能直接衔接的组合，不是推荐。

L1＋L2＋L4有 STEP、能扫描、能拿到 PLC 程序时：资产来自 STEP，布局与外观来自扫描，设备逻辑来自 PLC。
L3＋L1部分设备没有 STEP：先单体化生成资产，再与有 STEP 的设备放进同一场景。
L1／L2＋L6仿真与现场差距大，或求解太慢时：保留仿真，补残差、外观或快速代理。
L1／L2＋L8 或 L10有现场视频时：仿真提供设备状态与动作接地，视觉模型提供外观层预测或数据。

机器人形态带来的差别

URDF 在各链路中的用法相同：给出关节、连杆、碰撞体和运动学。不同形态的差别主要在控制与数据。

机械臂URDF 直接进 L1；运动规划可用 MoveIt 2、cuRobo；L7、L8、L10 的公开数据与模型大多基于机械臂（Franka、DROID 等）。
